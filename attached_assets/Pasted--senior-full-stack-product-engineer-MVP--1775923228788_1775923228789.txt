Ты — senior full-stack разработчик и product engineer. Твоя задача — разработать MVP веб-сервиса анализа конкурентности ключевых слов по Яндекс поисковой выдаче.

Нужно создать полноценное приложение, а не только backend.

Технологический стек:
- Backend: Python + FastAPI
- Frontend: React + TypeScript
- UI: современный, чистый, удобный
- Проект должен быть готов для запуска в Replit
- Интерфейс сервиса должен быть полностью НА РУССКОМ ЯЗЫКЕ
- Все пользовательские тексты, подписи кнопок, названия колонок, статусы, формы и сообщения об ошибках должны быть на русском языке
- Код можно писать на английском, но вся пользовательская часть — строго на русском

==================================================
1. ЦЕЛЬ СЕРВИСА
==================================================

Создать веб-сервис, который:

- принимает список ключевых слов
- анализирует ТОП-10 Яндекс SERP по каждому ключу
- определяет уровень конкуренции
- находит низкоконкурентные ключи
- показывает результаты в удобном интерфейсе
- позволяет экспортировать результаты в CSV и JSON

==================================================
2. ЧТО ДОЛЖНО БЫТЬ В СЕРВИСЕ
==================================================

Нужны две части:

1. Backend API
2. Frontend интерфейс

Frontend обязателен.

Пользователь должен иметь возможность через интерфейс:

- вставить список ключевых слов
- загрузить список ключей
- выбрать страну
- выбрать регион
- выбрать город
- выбрать режим геоанализа
- запустить анализ
- увидеть результаты в таблице
- отсортировать результаты
- скачать CSV / JSON

==================================================
3. ЖЁСТКИЕ ОГРАНИЧЕНИЯ ЛОГИКИ
==================================================

Сервис НЕ ДОЛЖЕН:

- генерировать новые ключевые слова
- расширять семантику
- делать кластеризацию
- анализировать интент
- делать смысловые выводы
- подменять исходный смысл ключа

Сервис ДОЛЖЕН:

- работать строго с переданным ключом
- учитывать словоформы
- учитывать перестановку слов
- НЕ считать разные сущности одинаковыми

Пример:

Ключ:
"купить квартиру с террасой москва"

Считаем совпадением:
- квартиры с террасой в москве
- купить квартиру москва терраса
- купить квартиру с террасой в москве

НЕ считаем:
- новостройки с террасой
- жк с террасой
- апартаменты с террасой

10. РАЗБОР КЛЮЧА
==================================================

Нужно выделять значимые леммы ключа.

Пример:

"купить квартиру с террасой москва"

→ ["купить", "квартира", "терраса", "москва"]

==================================================
11. АЛГОРИТМ СРАВНЕНИЯ
==================================================

Для каждого элемента выдачи:

1. Лемматизировать заголовок
2. Лемматизировать описание
3. Опционально лемматизировать title / h1 страницы

Считать покрытие:

coverage = совпавшие леммы / общее количество лемм ключа

==================================================
12. УРОВНИ СОВПАДЕНИЯ
==================================================

STRONG:
- coverage = 1.0
- все значимые леммы ключа присутствуют

NEAR:
- coverage >= 0.75

PARTIAL:
- 0.4 <= coverage < 0.75

NONE:
- coverage < 0.4

==================================================
13. СКОРИНГ
==================================================

SEO

Заголовок:
- STRONG = +6
- NEAR = +3
- PARTIAL = +1

Описание:
- STRONG = +2
- NEAR = +1
- PARTIAL = +0.5

Страница:
- STRONG = +1
- NEAR = +0.5
- PARTIAL = +0.2

ADS

Заголовок:
- STRONG = +3
- NEAR = +1.5
- PARTIAL = +0.5

Описание:
- STRONG = +1
- NEAR = +0.5
- PARTIAL = +0.2

Плотность рекламы:
- +0.5 за каждое объявление

Итоговая формула:

total_score = seo_score * 0.8 + ads_score * 0.2

Главный критерий конкурентности:

strong + near в органической выдаче
