Есть баг: столбец `Частотность` в таблице анализа появился, но для ключей, отправленных из Wordstat, там отображается `—`.

На скрине видно:

* в Wordstat-таблице у ключей есть частотность;
* я отправляю их в анализ;
* в таблице результатов анализа в колонке `Частотность` стоит `—`.

Значит, frequency где-то теряется между WordstatTable → sendToAnalysis → /api/analyze → AnalyzeResultItem → ResultsTable.

Нужно найти и исправить.

## Что проверить

### 1. WordstatTable

Проверьте, что кнопки:

* `Отправить выбранные в анализ`
* `Отправить все в анализ`

передают не массив строк, а массив объектов:

```json
[
  { "keyword": "конспект из аудио онлайн", "frequency": 17 },
  { "keyword": "конспект из аудио", "frequency": 225 }
]
```

Если сейчас в callback уходит только `row.keyword`, нужно передавать весь объект или явно `{ keyword, frequency }`.

---

### 2. HomePage / sendToAnalysis

Проверьте, что `sendToAnalysis` не превращает объекты обратно в строки.

Нужно поддерживать два варианта:

#### Ручной ввод / Search API

```json
["ключ 1", "ключ 2"]
```

#### Wordstat / Combined

```json
[
  { "keyword": "ключ 1", "frequency": 123 },
  { "keyword": "ключ 2", "frequency": 456 }
]
```

Если `sendToAnalysis` делает `.map(k => typeof k === "string" ? k : k.keyword)`, частотность будет потеряна. Так делать нельзя для Wordstat-сценария.

---

### 3. Backend /api/analyze

Проверьте, что backend:

* принимает оба формата;
* строит `frequency_by_keyword`;
* при создании каждого `AnalyzeResultItem` подставляет правильную частотность.

Важно:
сопоставление делать по нормализованному ключу, чтобы не ломаться из-за пробелов/регистра.

Пример:

```python
normalize_key(" Конспект из аудио ") == "конспект из аудио"
```

---

### 4. AnalyzeResultItem

Проверьте, что поле есть в response:

```json
{
  "keyword": "конспект из аудио",
  "frequency": 225,
  "class": "..."
}
```

Нужно посмотреть именно network response `/api/analyze`, а не только UI.

---

### 5. ResultsTable

Проверьте, что фронт читает именно то поле, которое отдаёт backend:

```ts
result.frequency
```

А не:

* `result.count`
* `result.wordstat_count`
* `result.freq`

Если backend отдаёт `frequency`, таблица должна читать `frequency`.

---

## Что должно получиться

После исправления сценарий должен работать так:

1. В Wordstat собрать ключи по запросу:
   `конспект из аудио`
2. Получить таблицу:

   * `конспект из аудио` — 225
   * `сделать конспект из аудио` — 46
   * и т.д.
3. Нажать `Отправить все в анализ`.
4. В таблице анализа в колонке `Частотность` должны быть эти же значения:

   * 225
   * 46
   * 36
   * 24
   * 17

Не `—`.

---

После исправления проверить:

* в XLSX лист `Ключи` содержит правильную частотность;
* в JSON `keywords[].frequency` не null;
* в ChatGPT markdown-таблице частотность заполнена.

Покажите:

1. Где именно терялась frequency.
2. Что приходит в request body `/api/analyze` из Wordstat.
3. Что возвращает response `/api/analyze` по одному ключу.
4. Что в таблице анализа теперь отображается частотность.
