Нужно доработать экспорт и таблицу анализа: сохранять и выводить частотность по ключам.

Сейчас частотность есть на этапе Wordstat, но дальше она может теряться при отправке ключей в анализ и при экспорте. Нужно протащить frequency/count по всему пайплайну.

## 1. Что нужно сделать

Добавить отдельное поле:

`Частотность`

или технически:

`frequency`

во все места, где отображаются или экспортируются результаты анализа.

Частотность должна сохраняться, если ключ пришёл из Wordstat.

Если ключ был введён вручную или загружен файлом и частотности нет, показывать:

* пусто
* `null`
* или `—`

Но не подставлять 0, чтобы не путать “нет данных” и “нулевая частотность”.

---

## 2. Где должна отображаться частотность

### 2.1. Таблица анализа конкуренции в интерфейсе

В итоговую таблицу анализа добавить столбец:

`Частотность`

Расположить его рядом с ключом, например:

* Ключ
* Частотность
* Класс
* Score
* Конкуренты
* SERP mix
* Рекомендация

Если частотности нет — показывать `—`.

---

### 2.2. XLSX-экспорт

В лист `Ключи` обязательно добавить колонку:

`Частотность`

Она должна быть рядом с колонкой `Ключ`.

Пример колонок:

* ключ
* частотность
* регион
* класс
* score
* уровень конкуренции
* SERP mix
* прямых конкурентов в top-10
* близких конкурентов в top-10
* рекомендация

В лист `Сводка` добавить:

* суммарная частотность по анализируемым ключам
* средняя частотность
* медианная частотность, если несложно
* топ-5 ключей по частотности

Если частотности нет ни у одного ключа, эти поля можно оставить пустыми или написать `нет данных`.

---

### 2.3. JSON для ChatGPT

В `analysis_data.json` в разделе `keywords` у каждого ключа должно быть поле:

```json
"frequency": 12345
```

Если частотности нет:

```json
"frequency": null
```

Также в `summary` добавить:

```json
"total_frequency": 0,
"average_frequency": 0,
"top_by_frequency": []
```

Если частотности нет, использовать `null` или пустые массивы.

---

### 2.4. analysis_summary.md

В Markdown-файле `analysis_summary.md` в таблице ключей должна быть колонка:

`Частотность`

Пример:

| Ключ | Частотность | Класс | Score | SERP mix | Прямых конкурентов | Рекомендация |
| ---- | ----------: | ----- | ----: | -------- | -----------------: | ------------ |

Также добавить блок:

`Топ ключей по частотности`

---

### 2.5. schema_explanation.md и лист `Справочник`

Добавить пояснение:

`Частотность` / `frequency` — количество запросов по данным Wordstat за последние 30 дней для выбранного региона. Если ключ был введён вручную или загружен файлом, частотность может быть неизвестна.

Важно:
не путать `frequency = null` и `frequency = 0`.

---

## 3. Важное по пайплайну

Когда пользователь в Wordstat-таблице нажимает:

* `Отправить выбранные в анализ`
* `Отправить все в анализ`
* или запускает комбинированный режим

нужно отправлять в analyze не только текст ключа, но и связанную с ним частотность.

То есть вместо массива строк, если нужно, использовать структуру:

```json
{
  "keyword": "аудио в текст онлайн",
  "frequency": 12345
}
```

Если backend сейчас принимает только строки, аккуратно расширить схему так, чтобы она поддерживала оба варианта:

1. старый формат:

```json
["ключ 1", "ключ 2"]
```

2. новый формат:

```json
[
  { "keyword": "ключ 1", "frequency": 123 },
  { "keyword": "ключ 2", "frequency": 456 }
]
```

Старый формат не ломать.

---

## 4. Где брать частотность

Источник частотности:

* Wordstat `results[].count`

Не брать частотность из `associations`, потому что основная Wordstat-таблица сейчас использует только `results`.

Если ключ пришёл из ручного ввода или файла:

* `frequency = null`
