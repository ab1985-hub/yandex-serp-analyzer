Нужно дожать интеграцию Wordstat не через спорный REST-маршрут, а рабочим способом.

Текущий статус принимаем как факт:

* Search API работает;
* `getRegionsTree` работает;
* `getTop` по REST на `POST /v2/wordstat/getTop` возвращает `404` с `x-envoy-response-flags: NR`;
* значит, дальше не тратим время на доказывание REST-маршрута, а делаем рабочую интеграцию через официальный SDK или gRPC.

Что нужно сделать:

## 1. Цель

Нужно добиться, чтобы в проекте реально заработал Wordstat `GetTop` для сценариев:

* Wordstat API
* Комбинированный режим

И чтобы пользователь мог:

* ввести seed-key;
* выбрать регион;
* задать лимит;
* получить список ключей с частотностью;
* отметить нужные чекбоксами;
* отправить выбранные или весь список в текущий анализ конкуренции.

## 2. Порядок реализации

Идём строго в таком порядке:

### Вариант A — через официальный Yandex AI Studio SDK

Сначала попробуйте поднять `GetTop` через официальный SDK Яндекса, а не через REST-маршрут.

Что нужно:

* проверить, установлен ли `yandex-ai-studio-sdk`;
* если нет — добавить в зависимости;
* сделать отдельный тестовый модуль/скрипт или сервисный метод для вызова Wordstat GetTop через SDK;
* использовать те же secrets:

  * `YANDEX_FOLDER_ID`
  * `YANDEX_API_KEY`

Нужно получить рабочий вызов:

* phrase = `"купить квартиру"`
* num phrases = 5
* region = `"213"`

Если SDK возвращает данные:

* встроить этот способ в `app/services/yandex_client.py`;
* сделать SDK основным транспортом для `wordstatGetTop()`;
* `getRegionsTree` можно оставить как есть, если текущая реализация уже работает.

### Вариант B — через gRPC

Если SDK не позволяет нормально вызвать `GetTop` или внутри всё равно упирается в тот же нерабочий REST, тогда делайте прямую gRPC-интеграцию.

Что нужно:

* не использовать `grpcurl` как runtime-решение;
* реализовать вызов из Python-кода;
* подключить `grpcio`, `grpcio-tools` или другой корректный стек;
* использовать официальные proto / stubs Яндекса, если они доступны;
* собрать клиент для WordstatService.GetTop.

Нужен нормальный программный вызов из backend, а не ручная команда в консоли.

## 3. Что именно нужно получить в коде

В `app/services/yandex_client.py` или рядом должен появиться реальный рабочий метод:

* `wordstat_get_top(...)`

Сигнатура примерно такая:

* phrase
* num_phrases
* regions
* folder_id
* при необходимости devices

Метод должен возвращать унифицированную структуру для фронта:

* `phrase`
* `count`

То есть в UI таблицу Wordstat должны уходить уже готовые строки:

* ключ
* частотность

## 4. UI не ломать

Важно:

* текущий Search API режим не трогать, он уже работает;
* текущую таблицу анализа конкуренции не трогать;
* текущую логику вывода анализа не трогать;
* режимы и Wordstat-таблицу сохранить как есть;
* нужно только заменить транспорт получения `GetTop` на рабочий.

## 5. Что оставить fallback

Можно оставить:

* `GetRegionsTree` как текущую рабочую реализацию;
* fallback-список регионов только как резерв, если API реально недоступен.

Нельзя оставлять:

* “заглушку вместо GetTop”;
* фиктивные данные;
* утверждение, что Wordstat работает, если реально нет живого ответа.

## 7. Если SDK или gRPC требуют отдельной инфраструктуры

Если упрётесь в установку proto, stubs или transport-слой:

* не останавливайтесь;
* сделайте минимально рабочий backend-клиент;
* опишите, что именно добавили в зависимости и почему.

## 8. Формат работы

Не нужно больше теоретических рассуждений о том, почему REST-маршрут не работает.
Нужно практически дожать Wordstat до рабочего состояния через SDK или gRPC.

Начинайте с варианта SDK.
Если SDK не даёт рабочий `GetTop`, сразу переключайтесь на gRPC.
После этого покажите конкретный рабочий результат.
