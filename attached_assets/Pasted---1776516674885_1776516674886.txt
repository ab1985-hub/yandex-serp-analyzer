Нужно добавить понятную выгрузку результатов анализа.

Цель:
пользователь должен иметь возможность выгрузить результаты:

1. для самостоятельного анализа в Excel;
2. для отправки в ChatGPT на дальнейший разбор в другой ветке.

Важно:
выгрузка должна быть не просто техническим JSON, а понятным пакетом данных с пояснениями, чтобы другой человек или ChatGPT в новой ветке мог быстро понять:

* что анализировалось;
* что означают классы A/B/C/D;
* что такое score;
* что такое SERP mix;
* что такое direct / close / indirect competitor;
* что значат типы страниц;
* что значат уровни закрытия интента.

---

## 1. Добавить экспорт XLSX

Сделать кнопку:

`Экспорт в XLSX`

Файл должен быть человекочитаемым и состоять из нескольких листов.

---

### Лист 1 — `Сводка`

Поля:

* дата анализа
* режим анализа: Search API / Wordstat / Combined
* регион
* количество ключей
* средний score
* распределение по классам A/B/C/D
* количество ключей с низкой / умеренной / высокой / очень высокой конкуренцией
* количество ключей с HOMOGENEOUS / MIXED / STRONGLY_MIXED выдачей
* суммарное количество прямых конкурентов
* суммарное количество близких конкурентов
* среднее количество прямых конкурентов на ключ
* среднее количество HTML-загрузок на ключ
* краткое пояснение шкалы

---

### Лист 2 — `Ключи`

Колонки:

* ключ
* частотность, если есть
* регион
* класс
* score
* уровень конкуренции
* SERP mix
* прямых конкурентов в top-10
* близких конкурентов в top-10
* непрямых конкурентов в top-10
* не конкурентов в top-10
* сколько HTML-страниц загружено
* сколько HTML-страниц не загружено
* сколько страниц сильно закрывают интент
* сколько страниц частично закрывают интент
* сколько tool/service/converter страниц
* причина guardrail / class adjustment, если есть
* рекомендация

---

### Лист 3 — `SERP детали`

По каждой строке органической выдачи:

* ключ
* позиция
* домен
* URL
* title
* description / snippet
* тип по SERP
* тип по HTML
* конкурент
* закрытие интента
* fetch status
* вклад в score
* текстовое совпадение
* гео-тип, если есть
* комментарий / причина классификации, если есть

---

### Лист 4 — `Wordstat`

Если анализ начинался со сбора Wordstat, добавить:

* ключ
* частотность
* выбран / не выбран
* исключён минус-фразой или нет
* источник: results / manual / file, если доступно

Если Wordstat-данных нет, лист можно не создавать.

---

### Лист 5 — `Справочник`

Обязательно добавить справочный лист с пояснениями.

На нём описать значения:

#### Классы конкуренции

* `A` — низкая конкуренция / хороший кандидат
* `B` — умеренная конкуренция / можно брать в работу
* `C` — высокая конкуренция / заходить осторожно
* `D` — очень высокая конкуренция / плотная выдача

#### Score

Пояснить:

* score — числовая оценка конкурентности;
* чем выше score, тем сложнее запрос;
* указать текущие пороги A/B/C/D, которые реально используются в проекте.

#### SERP mix

* `HOMOGENEOUS` — однородная выдача: в топе преобладает один тип страниц
* `MIXED` — смешанная выдача: в топе есть несколько разных типов страниц
* `STRONGLY_MIXED` — сильно смешанная / неопределённая выдача: Яндекс показывает разные форматы ответа, есть SEO-возможность

#### Конкурентный статус

* `DIRECT` / `Прямой` — страница решает ту же задачу и является прямым конкурентом
* `CLOSE` / `Близкий` — страница частично решает ту же задачу или является смежным конкурентом
* `INDIRECT` / `Непрямой` — страница отвечает на тему, но не даёт такого же продуктового решения
* `NOT_COMPETITOR` / `Не конкурент` — результат не является конкурентом
* `Не загружено` — HTML страницы не удалось получить, используется только SERP-layer

#### Типы страниц

* `TOOL_SERVICE` — онлайн-инструмент / сервис
* `CONVERTER` — конвертер / транскрибатор / tool-page
* `SAAS` — SaaS / web-app
* `LANDING` — продуктовый лендинг
* `ARTICLE` — информационная статья
* `REVIEW_LIST` — обзор / подборка / список сервисов
* `DOCS` — документация / help / support
* `MARKETPLACE` — маркетплейс / каталог
* `FORUM` — форум / user-generated content
* `IRRELEVANT` — нерелевантный результат

#### Закрытие интента

* `STRONG` / `Сильно закрывает` — страница хорошо решает задачу пользователя
* `PARTIAL` / `Частично закрывает` — страница решает задачу частично
* `WEAK` / `Слабо закрывает` — страница слабо соответствует интенту
* `NONE` / `Не закрывает` — страница не закрывает интент

#### Fetch status

* `fetch_ok=true` — HTML страницы успешно загружен и проанализирован
* `fetch_ok=false` — HTML страницы не загружен, анализ основан только на SERP-данных

#### Guardrails

Пояснить:

* guardrail — правило, которое корректирует итоговый класс, если deep-analysis показывает слишком плотную конкурентную выдачу;
* например, если много прямых конкурентов и выдача однородная, класс не может быть `A`.

## 2. Добавить экспорт для ChatGPT

Сделать кнопку:

`Экспорт для ChatGPT`

Эта выгрузка должна быть удобна для отправки в новую ветку ChatGPT.

Вариант MVP:
сформировать `.zip`, внутри которого:

1. `analysis_summary.md`
2. `analysis_data.json`
3. `schema_explanation.md`

Если zip сложно сделать на первом этапе, можно скачать эти файлы по отдельности. Но лучше zip.

---

### Файл 1 — `analysis_summary.md`

Это человекочитаемое резюме.

В нём должно быть:

* дата анализа
* режим анализа
* регион
* список анализируемых ключей
* краткая сводка по классам A/B/C/D
* таблица ключей:

  * ключ
  * частотность
  * класс
  * score
  * SERP mix
  * прямых конкурентов
  * близких конкурентов
  * рекомендация
* топ перспективных ключей
* топ самых конкурентных ключей
* краткое пояснение, как читать результаты

---

### Файл 2 — `analysis_data.json`

Это полный структурированный файл для машинного анализа.

В нём должны быть разделы:

```json id="jmduwo"
{
  "metadata": {
    "exported_at": "",
    "analysis_mode": "",
    "region": "",
    "keywords_count": 0,
    "source": "seo-machine-yandex-search-api-wordstat-api",
    "schema_version": "1.0"
  },
  "legend": {},
  "keywords": [],
  "serp_details": [],
  "wordstat": [],
  "summary": {}
}
```

#### `metadata`

Поля:

* `exported_at`
* `analysis_mode`
* `region`
* `keywords_count`
* `source`
* `schema_version`

#### `legend`

В JSON обязательно добавить объект `legend`, чтобы ChatGPT в другой ветке мог понять значения.

В `legend` описать:

* `competition_classes`
* `score`
* `serp_mix`
* `competitor_levels`
* `page_types`
* `intent_coverage`
* `fetch_status`
* `guardrails`

#### `keywords`

По каждому ключу:

* keyword
* frequency
* region
* class
* score
* competition_level
* serp_mix
* direct_count
* close_count
* indirect_count
* not_competitor_count
* html_loaded_count
* html_failed_count
* strong_intent_count
* partial_intent_count
* tool_like_count
* class_guardrail_reason
* recommendation

#### `serp_details`

По каждой строке выдачи:

* keyword
* position
* domain
* url
* title
* description
* page_type_serp
* page_type_html
* competitor_level
* intent_coverage
* fetch_ok
* score_contribution
* text_match_level
* geo_type
* classification_comment

#### `wordstat`

Если есть Wordstat-данные:

* phrase
* count
* selected
* excluded_by_minus
* source

#### `summary`

* average_score
* class_distribution
* serp_mix_distribution
* total_direct_competitors
* total_close_competitors
* best_opportunities
* hardest_keywords

### Файл 3 — `schema_explanation.md`

Это отдельное пояснение к данным.

В нём описать:

1. Что это за выгрузка.
2. Как был собран анализ:

   * Yandex Search API
   * Wordstat API, если использовался
   * deep-analysis top-10
3. Что означает каждый раздел JSON.
4. Как читать классы A/B/C/D.
5. Как читать SERP mix.
6. Как читать competitor_level.
7. Как читать intent_coverage.
8. Как читать page_type_html.
9. Что значит fetch_ok.
10. Что значит class_guardrail_reason.
11. Какие ограничения есть у анализа:

    * часть страниц может не загрузиться;
    * JS-only страницы без рендера могут анализироваться неполно;
    * классификация rule-based, не абсолютная;
    * Wordstat-частотность зависит от API Яндекса и региона.

## 3. Где разместить кнопки

Кнопки экспорта должны быть рядом с итоговой таблицей анализа:

* `Экспорт XLSX`
* `Экспорт JSON`
* `Экспорт для ChatGPT`

Если таблица пустая — кнопки disabled.

---

## 4. Важные требования

* не ломать текущий экспорт Wordstat;
* не ломать текущую таблицу анализа;
* экспорт должен использовать те же данные, которые сейчас отображаются в интерфейсе;
* если часть HTML-страниц не загрузилась, это должно быть видно в выгрузке;
* русские названия колонок в XLSX;
* в JSON использовать стабильные технические enum-значения + добавить человекочитаемые labels в legend;
* не терять deep-analysis поля;
* не терять guardrail-пояснения;
* если каких-то данных нет, оставлять `null`, пустую строку или пустой массив, но не ломать экспорт.

---

## 5. Что проверить

После реализации проверить на 3 ключах:

* `аудио в текст онлайн`
* `как перевести аудио в текст`
* `конспект лекции`

Показать:

1. что XLSX скачивается и открывается;
2. какие листы есть в XLSX;
3. что в XLSX есть лист `Справочник`;
4. что JSON содержит:

   * metadata
   * legend
   * keywords
   * serp_details
   * summary
5. что `schema_explanation.md` понятно объясняет значения;
6. что экспорт для ChatGPT можно скачать и он содержит достаточно пояснений для анализа в другой ветке;
7. что текущий Wordstat-экспорт не сломался.
