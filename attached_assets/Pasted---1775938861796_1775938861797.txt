Нужно сделать следующую итерацию доработки текущего сервиса анализа конкурентности ключевых слов по Яндекс SERP.

То, что уже сделано, — это шаг в правильную сторону:
- разделено текстовое совпадение и конкурентный вес;
- введены типы страниц;
- информационные материалы стали понижаться по весу;
- debug стал гораздо полезнее.

Но сейчас сервис всё ещё недостаточно точен для практического отбора низкоконкурентных SEO-ключей.

НУЖНО ДОРАБОТАТЬ ЛОГИКУ ЕЩЁ НА ОДИН УРОВЕНЬ.

ГЛАВНЫЕ ПРОБЛЕМЫ, КОТОРЫЕ ЕЩЁ ОСТАЛИСЬ

1. В деталях анализа до сих пор не хватает самого важного для ручной проверки — ссылки на конкретную страницу результата.
Пользователь должен сразу видеть, на какую именно страницу ведёт результат.

2. Не хватает отдельного бинарного признака:
- прямой конкурент
- не прямой конкурент

Сейчас есть тип страницы и конкурентный вес, но этого недостаточно.
Для SEO-решений нужно явно видеть:
это прямой конкурент по нужному спросу или нет.

3. Не хватает учёта гео-релевантности.
Если регион анализа — Москва, а в рекламе или органике результат из Омска, Новороссийска, Мариуполя и т.п., такой результат не должен получать тот же вес, что локально релевантный.
Гео-нерелевантные страницы и объявления должны понижаться по весу.

4. Категория «Смешанный» сейчас слишком расплывчатая.
Её нужно доразбить, чтобы debug стал полезнее и точнее.

ЧТО НУЖНО СДЕЛАТЬ

1. Добавить в детали анализа отдельный столбец:
- «Ссылка»
или
- «Посадочная страница»

Это обязательное требование.

Нужно:
- добавить этот столбец в органическую выдачу
- добавить этот столбец в рекламную выдачу
- если URL доступен — показывать его в таблице
- ссылка должна быть кликабельной
- ссылка должна открываться в новой вкладке
- можно сокращать визуально отображение длинных URL, но сам href должен быть реальным

Это нужно, чтобы пользователь мог руками сразу проверить:
- это карточка ЖК
- это каталог
- это статья
- это госстраница
- это нерелевантный материал

2. Добавить отдельный признак:
- «Прямой конкурент»

Это должен быть отдельный столбец или отдельный бейдж в деталях анализа.

Нужно явно показывать:
- Да
- Нет

Логика:
Прямой конкурент — это результат, который реально конкурирует за тот же SEO/коммерческий спрос в недвижимости.

Примеры прямого конкурента:
- карточка объекта
- каталог недвижимости
- страница застройщика
- агрегатор недвижимости
- коммерческая посадочная по выбору/покупке/продаже квартиры

Примеры не прямого конкурента:
- статья про дизайн квартиры
- статья про льготы
- ипотечная справка
- госстраница
- медиа-материал, совпадающий только по словам

Нужен именно отдельный бинарный вывод, а не только вес.

3. Добавить гео-релевантность результата.

Это очень важно.

Если анализ идёт по региону Москва, а страница/реклама явно про другой город или регион, это должно понижать её вклад в конкуренцию.

Нужно добавить отдельную проверку:
- локально релевантен
- гео-сомнителен
- гео-нерелевантен

Можно определить хотя бы по:
- заголовку
- описанию
- URL
- домену
- названиям городов/регионов в тексте

Примеры:
- Москва / Московская область при анализе по Москве → релевантно
- Россия без явного города → нейтрально / умеренно релевантно
- Омск / Новороссийск / Мариуполь при анализе по Москве → гео-нерелевантно

Нужно, чтобы гео-нерелевантность уменьшала конкурентный вес.

Пример логики:
- гео-релевантно → множитель 1.0
- гео-нейтрально → множитель 0.7
- гео-нерелевантно → множитель 0.3 или 0.2

Точную формулу можешь выбрать сам, но она должна быть прозрачной и объяснимой.

4. Доразбить типы страниц.

Сейчас «Смешанный» слишком широкий класс.
Нужно сделать типизацию точнее.

Минимально нужны такие категории:
- Коммерческий конкурент
- Агрегатор / каталог недвижимости
- Карточка объекта / застройщик / ЖК
- Коммерческо-информационный материал
- Информационная статья
- Государственная / справочная страница
- Нерелевантный материал

Можно использовать чуть другие названия, но смысл должен быть таким.

Цель:
чтобы debug был реально полезным и показывал, что именно найдено.

5. Пересчитать итоговый вклад результата не только по тексту и типу страницы, но и с учётом гео-релевантности.

Новая логика должна учитывать минимум 3 слоя:

Слой 1:
Текстовое совпадение

Слой 2:
Тип страницы / конкурентный интент

Слой 3:
Гео-релевантность

То есть итоговый вклад результата должен зависеть не только от:
- совпадения слов
- типа страницы

но и от:
- релевантности региону поиска

6. Улучшить debug-панель.

Для каждого результата в деталях анализа нужно показать:

- Заголовок
- Описание
- Ссылка / посадочная страница
- Текстовое совпадение
- Тип страницы
- Прямой конкурент: Да/Нет
- Гео-релевантность
- Итоговый конкурентный вес
- Пояснение, почему результат считается или не считается значимым конкурентом

Пример пояснений:
- «Информационная статья о дизайне, не является прямым конкурентом покупке квартиры»
- «Коммерческий агрегатор недвижимости, прямой конкурент»
- «Результат гео-нерелевантен региону анализа, вес снижен»
- «Госстраница совпадает по словам, но не конкурирует за коммерческий спрос»

7. Полностью сохранить русский язык интерфейса.

Во всей пользовательской части интерфейса не должно быть английских слов.
Если где-то после прошлой доработки ещё остались английские термины, убери их.

Все обозначения должны быть на русском:
- типы страниц
- гео-релевантность
- прямой конкурент
- совпадения
- пояснения
- debug-блоки
- столбцы таблицы

ЧТО НУЖНО ПОЛУЧИТЬ В ИТОГЕ

После доработки сервис должен:
- показывать ссылку на каждую страницу в деталях анализа
- явно показывать, является ли результат прямым конкурентом
- учитывать гео-релевантность
- понижать вес результатов из нерелевантных городов/регионов
- точнее разделять типы страниц
- давать более адекватную итоговую оценку конкурентности
- иметь понятный и полностью русский debug

ВАЖНО
Не ломай текущий интерфейс без необходимости.
Работай аккуратно в рамках текущей архитектуры.
Если нужно, меняй и backend, и frontend.
Если нужно, добавь поля в типы, схемы, debug-структуры и таблицы.
Если нужно, обнови scorer, classifier, reporter и frontend-компоненты деталей анализа.
