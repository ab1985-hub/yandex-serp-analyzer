Нужно добавить в Wordstat-режим дополнительный UX-функционал по логике плагина UTA-Manager.

Цель:
пользователь должен иметь возможность не только отмечать целые фразы чекбоксами, но и выделять отдельные слова внутри фраз, а затем одной кнопкой переносить выбранные слова в поле `Минус-фразы (по одной на строку)`.

Важно:
это не логика самого Wordstat API, а дополнительный интерфейсный инструмент поверх нашей Wordstat-таблицы.

## Что нужно реализовать

### 1. Выделение отдельных слов внутри фраз

В таблице Wordstat, в колонке `Ключ`, каждую фразу нужно визуально разбить на отдельные токены-слова.

Пример:
`собака для семьи с детьми в квартиру`

Должно отображаться как набор кликабельных слов:

* собака
* для
* семьи
* с
* детьми
* в
* квартиру

При клике по слову:

* слово должно визуально выделяться;
* повторный клик снимает выделение;
* выделение должно работать независимо от чекбоксов строк.

То есть в таблице должно быть два независимых механизма:

1. чекбоксы строк — для отправки целых ключей в анализ;
2. клик по словам — для набора минус-слов.

### 2. Панель работы с выбранными словами

Над таблицей Wordstat, рядом с блоком действий, добавить отдельную кнопку:

`Исключить минус-слова`

Логика:

* пользователь накликал одно или несколько слов в таблице;
* нажимает `Исключить минус-слова`;
* все выбранные слова добавляются в textarea `Минус-фразы (по одной на строку)`.

### 3. Правила переноса слов в минус-фразы

При нажатии кнопки:

* добавляются только уникальные слова;
* не дублировать слова, которые уже есть в поле минус-фраз;
* каждое слово добавляется с новой строки;
* порядок можно делать в порядке выбора или в алфавитном — предпочтительно в порядке выбора;
* после переноса:

  * либо очищать текущее выделение слов,
  * либо оставлять выделение только до следующего обновления таблицы.

Предпочтительно:

* после успешного переноса очищать выделение слов, чтобы UX был чище.

### 4. Что считать словом

На первом этапе достаточно простой токенизации:

* разбивать по пробелам;
* очищать внешние знаки препинания;
* приводить к нижнему регистру только для внутреннего сравнения уникальности;
* отображать пользователю слово в исходной форме, как оно было во фразе.

Пример:
`квартиры,`
в UI можно показать как `квартиры`,
но при добавлении в минус-фразы сохранить чистую форму без запятой.

### 5. Что не нужно делать пока

Пока не нужно:

* морфологически объединять формы слов;
* автоматически минусовать словосочетания;
* делать сложный NLP-разбор;
* добавлять отдельный режим фразовых минус-слов.

На этом этапе нужны только отдельные слова.

### 6. Где именно это должно работать

Этот функционал нужен в Wordstat-таблице после получения списка ключей.

То есть сценарий такой:

1. пользователь собирает ключи через Wordstat;
2. видит таблицу;
3. кликает на отдельные слова внутри фраз;
4. нажимает `Исключить минус-слова`;
5. слова появляются в поле `Минус-фразы`;
6. потом пользователь может заново собрать ключи уже с обновлёнными минус-фразами.

### 7. Визуальное поведение

Слова должны выглядеть интерактивными:

* cursor pointer;
* лёгкий hover;
* выбранное слово заметно подсвечено;
* желательно аккуратный chip/tag-style или inline-highlight.

Но не нужно перегружать интерфейс.

### 8. Важные ограничения

* не ломать текущую таблицу Wordstat;
* не ломать чекбоксы по строкам;
* не ломать отправку выбранных ключей в анализ;
* не ломать экспорт;
* поле `Минус-фразы` должно оставаться обычным редактируемым textarea.

### 9. Техническая реализация

Сделать это на фронте.

Ожидаемо, изменения будут в компонентах типа:

* `WordstatTable`
* `WordstatForm`
* возможно `HomePage` / родительский контейнер состояния

Нужен отдельный state для выбранных слов, например:

* `selectedMinusWords: string[]`

Нужен callback вида:

* `onAddMinusWords(words: string[])`

И передача этого callback в форму, где находится textarea `Минус-фразы`.
