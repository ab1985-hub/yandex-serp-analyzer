Deep-analysis стал заметно лучше, но сейчас есть две проблемы:

1. В debug-таблице дублируется смысл колонок:

* есть колонка `Конкурент`;
* есть отдельная колонка `Прямой`;
* из-за этого непонятно, какая колонка является главной.

2. Deep-analysis сейчас, похоже, применяется не ко всему топу, поэтому часть явных сервисов остаётся без нормальной HTML-классификации и не определяется как прямой конкурент, хотя по смыслу это такие же сервисы / конвертеры.

Нужно доработать это.

## 1. Убрать отдельный столбец `Прямой`

Отдельный столбец `Прямой` больше не нужен.

Оставить один главный столбец:

`Конкурент`

В нём показывать один из статусов:

* `Прямой`
* `Близкий`
* `Непрямой`
* `Не конкурент`
* `Не загружено`
* `Не определено`

Вся конкурентная логика должна быть сосредоточена только в этом столбце.

Не должно быть ситуации, где в одном столбце написано `Конкурент = Прямой`, а в другом ещё раз `Прямой`.

## 2. Deep-analysis должен применяться ко всему топ-10

Сейчас top-5 недостаточно. По запросам типа:

* `аудио в текст онлайн`
* `из аудио в текст`
* `аудио в текст`
* `транскрибация аудио`

в топ-10 почти все результаты могут быть сервисами, конвертерами или SaaS-страницами. Если анализировать только первые 5, нижние строки остаются недооценены.

Нужно расширить углублённый анализ на весь органический top-10.

Что должно быть:

* для всех 10 органических результатов пытаться догрузить HTML;
* для каждой строки определить:

  * `page_type_html`
  * `competitor_level`
  * `intent_coverage`
  * `fetch_ok`
* если страница не загрузилась, анализ не падает, строка получает `fetch_ok = false`.

## 3. Deep-analysis должен работать по умолчанию

Отдельная галка `Углублённый анализ` больше не нужна.

Логика должна быть такой:

* пользователь запускает анализ;
* система по умолчанию делает SERP-анализ + HTML-анализ top-10;
* в таблице сразу показывается качественная классификация.

То есть deep-analysis должен стать стандартным поведением анализа.

Если в коде нужен флаг для совместимости, можно оставить внутренний параметр:

* `deep_analysis = true` по умолчанию

Но в пользовательском интерфейсе отдельную галку лучше убрать, чтобы не плодить лишние настройки.

## 4. Если нужна защита по скорости

Понимаю, что top-10 HTML-fetch может быть медленнее.

Но вместо отдельной галки сделайте нормальную техническую защиту:

* параллельная загрузка страниц через async;
* разумный timeout;
* один retry;
* если часть страниц недоступна — не валить весь анализ;
* показывать `Не загружено` по конкретным строкам;
* не ждать бесконечно медленные сайты.

Цель:
лучше чуть дольше, но качественнее, чем быстрый анализ, который неверно определяет конкурентов.

## 5. Как должна работать колонка `Конкурент`

### Если HTML успешно загружен

Использовать статус из page-analysis:

* `DIRECT` → `Прямой`
* `CLOSE` → `Близкий`
* `INDIRECT` → `Непрямой`
* `NOT_COMPETITOR` → `Не конкурент`

### Если HTML не загружен

Не писать уверенно `Прямой`, если это не подтверждено HTML.

Варианты:

* показывать `Не загружено`;
* либо показывать базовую оценку с пометкой `по SERP`.

Предпочтительно:

* если HTML не загрузился, показывать `Не загружено`;
* при этом backend может использовать базовую SERP-логику для score, но UI должен честно показывать, что HTML-подтверждения нет.

## 6. Приоритет HTML-layer

Если SERP-layer говорит одно, а HTML-layer другое, то при `fetch_ok = true` приоритет должен быть у HTML-layer.

Пример:

* базовый SERP-слой определил `Информационная статья`;
* HTML-layer определил `Конвертер`;
* итоговый тип должен считаться как `Конвертер`;
* конкурентный статус должен быть `Прямой`, если страница реально даёт сервисную функцию.

Это особенно важно для страниц, где сниппет выглядит как статья, но внутри есть инструмент.

## 7. Почему часть строк сейчас не стала прямыми конкурентами

Нужно проверить текущую логику:

* возможно, deep-analysis применяется только к top-5;
* возможно, для строк без HTML оставляется старый слабый статус;
* возможно, classifier слишком строгий и не видит сервис по title/url/snippet;
* возможно, tool/service признаки не распознаются для английских и русских формулировок.

Нужно исправить так, чтобы явные сервисы / конвертеры / transcription tools в top-10 не оставались случайно `не конкурентами`.

Для запросов типа `аудио в текст онлайн` большинство сервисов с функцией конвертации аудио в текст должны быть:

* `TOOL_SERVICE` / `CONVERTER` / `SAAS`
* `Прямой` или минимум `Близкий`
* `Сильно закрывает` или минимум `Частично закрывает`

## 8. SERP mix

SERP mix должен считаться уже с учётом всей структуры top-10.

Если 8–10 результатов являются сервисами / конвертерами / SaaS — это:

* `HOMOGENEOUS`
* однородная выдача
* конкуренция выше

Если результаты перемешаны:

* статьи,
* сервисы,
* обзоры,
* форумы,
* случайные страницы,

то это:

* `MIXED`
  или
* `STRONGLY_MIXED`

## 9. Что проверить после исправления

Прогоните два запроса:

1. `аудио в текст онлайн`
2. `как перевести аудио в текст`

Для первого запроса ожидаем:

* большинство результатов top-10 — сервисы / конвертеры;
* в колонке `Конкурент` много `Прямой`;
* SERP mix скорее `Однородная выдача`;
* score должен отражать заметную конкуренцию.

Для второго запроса ожидаем:

* выдача более смешанная;
* часть результатов — статьи / инструкции;
* часть — сервисы;
* SERP mix скорее `Смешанная`;
* статьи не должны приравниваться к прямым сервисам.

## 10. Что показать после исправления

Покажите:

1. Что столбец `Прямой` удалён.
2. Что остался один столбец `Конкурент`.
3. Что deep-analysis применяется ко всему top-10.
4. Что отдельной галки deep-analysis больше нет, либо deep-analysis включён по умолчанию и не требует ручного включения.
5. Как отображаются строки, если HTML не загрузился.
6. Повторный прогон:

   * `аудио в текст онлайн`
   * `как перевести аудио в текст`

Главная цель:
сделать анализ понятным и качественным по умолчанию: пользователь запускает анализ и сразу получает нормальную оценку top-10, где сервисы, конвертеры и прямые конкуренты определяются корректно.
